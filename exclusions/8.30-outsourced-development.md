## Control 8.30: Outsourced Development

### Exclusion Statement
This control is NOT APPLICABLE to CloudNative Analytics Ltd.

### Business Context
CloudNative Analytics performs all software development — including the core
SaaS platform and the ML-powered Insight Recommendations feature — entirely
in-house, using directly employed engineers. The company has no contracts,
agreements, or working relationships with any third-party or outsourced
development firms, freelance development shops, or offshore development
vendors.

### Risk Assessment Linkage
Because no outsourced development exists, the risks this control is designed
to mitigate (loss of code oversight, IP leakage to a third party, inconsistent
security standards from an external vendor) are not present in this
organization's operating model. No alternative control is required, since
there is no residual risk to compensate for — this is a genuine absence of
applicability, not a gap.

| Risk Addressed by 8.30 (Not Present Here) | Why It Doesn't Apply |
|---|---|
| Vendor code not meeting internal security standards | All code written internally under 8.28 secure coding standards |
| IP/source code exposure to a third party | Source access restricted to employees only under 8.4 |

### Evidence of Non-Applicability
- Engineering org chart showing 100% employed (not contracted) development staff
- Vendor/supplier register, which contains no development-related entries
- Source code repository access logs showing only employee accounts

### Auditor Anticipated Questions

Q: "Do you use any contractors or freelancers for development work at all?"
A: No. All development, including the ML feature, is performed by full-time
   employees. This is confirmed in the engineering org chart and HR records.

Q: "What if that changes in the future — do you have a policy ready?"
A: Not currently, since the scenario hasn't arisen. If outsourced development
   is introduced, this control would need to move from excluded to applicable,
   and a vendor security assessment process (extending 5.19–5.22) would need
   to be established before any such engagement begins.

### Conditions for Re-evaluation
This exclusion should be re-evaluated immediately if the company engages any
outsourced, contracted, or third-party development resource for any part of
the platform, including the ML pipeline.
